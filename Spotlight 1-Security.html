Echo API

Security & Privacy Architecture

Overview

Echo API is built with a "Security First" approach, ensuring that user data remains private, isolated, and secure at every stage of the lifecycle. This document outlines the technical measures we employ to protect your data.

1. Multi-Tenant Isolation

Echo API utilizes strict multi-tenancy enforcement to ensure no data leakage between users.

  • Tenant Identification: Every API request is authenticated via the RapidAPI Gateway, which assigns a unique, immutable User ID to the request.
  • Data Partitioning: Customer data is stored in isolated document collections within our Firestore database.
  • Access Control: Our backend strictly validates that the requesting User ID matches the Data Owner ID for every read and write operation. It is mathematically impossible for User A to access User B's logs.

2. Encryption Standards

  • In-Transit: All data transmitted between your application, the RapidAPI Gateway, and our servers is encrypted using TLS 1.2+ (Transport Layer Security).
  • At-Rest: All data stored in our databases is encrypted at rest using AES-256 standards managed by Google Cloud Platform.

3. AI Data Privacy

  • Processing: Data sent to our AI engine is used strictly for processing the request (summarization and tagging).
  • No Training: We do not use your customer data to train our public AI models. Your user's journal entries remain their own.

4. Infrastructure Security

Our backend is hosted on Render's secure cloud infrastructure, which provides:

  • DDoS Protection
  • Automated OS Patching
  • Private Networking between services
